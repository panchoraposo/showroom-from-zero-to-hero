= Update Code with Dev Spaces

This module walks through **edit in web IDE -> commit to Gitea -> Tekton pipeline -> new deployment**, using **Red Hat OpenShift Dev Spaces** and the **neuralbank-backend** component.

== Open the Component in Developer Hub

. Log in to **Developer Hub**.
. Find **neuralbank-backend** in the **Catalog** and open its page.
. Click **Open in Dev Spaces** (or the equivalent plugin action).

If the button is missing, copy the repository URL from Gitea and create a workspace in Dev Spaces manually.

== Wait for the Workspace to Start

. Wait until **DevWorkspace** reaches **Running** state.
. Open the IDE in the browser.

The workspace uses the `devfile.yaml` generated by the template:

[source,yaml]
----
schemaVersion: 2.2.2
metadata:
  name: neuralbank-backend
components:
  - name: tools
    container:
      image: registry.redhat.io/devspaces/udi-rhel9:latest
      memoryLimit: 4Gi
      cpuLimit: "2"
      mountSources: true
commands:
  - id: 01-build
    exec:
      component: tools
      commandLine: <...>
      workingDir: ${PROJECT_SOURCE}
  - id: 02-run
    exec:
      component: tools
      commandLine: <...>
      workingDir: ${PROJECT_SOURCE}
----

== Develop in Dev Spaces (tasks from the devfile)

In this section you will use Dev Spaces to inspect the devfile, scan dependencies with RHDA, build and run the app, access Quarkus Dev UI + Swagger, make a small code change, and push it back to Git.

.1. Review the `devfile.yaml`
. Open `devfile.yaml` in the repository root.
. Read it and identify the key pieces:
* Workspace container resources (CPU/memory) under `components[].container`.
* The available commands (these show up as tasks) and what they do:
** `01-build` runs `mvn compile -DskipTests`
** `02-run` runs `mvn quarkus:dev` for live reload
. Also open `.mvn/maven.config` and `.mvn/settings.xml` to see how Maven is configured to use the in-cluster Nexus.

== Dependency Analytics (RHDA) in Dev Spaces

This step uses the *Red Hat Dependency Analytics* (RHDA) extension to scan `pom.xml` and generate a dependency/vulnerability report.

.2. Activate RHDA and review `pom.xml`
. Open `pom.xml`.
. Ensure the *Red Hat Dependency Analytics* extension is enabled:
* Open the *Extensions* view.
* Search for `Dependency Analytics` (publisher `redhat`, extension `fabric8-analytics`) and enable/install it if needed.
. Generate the report:
* Right click `pom.xml` and run *Red Hat Dependency Analytics Report...* (or use the command palette).
. Review the report and discuss a few findings:
* *Why CVEs appear*: often due to **transitive** dependencies pulled in by a framework (Quarkus, Netty, Jackson, etc.).
* *Severity vs exploitability*: explain that severity is a starting point; context matters (network exposure, reachable code paths, configuration).
* *Remediation*: prefer upgrading the platform/BOM, then verify the dependency tree changed as expected.

== Build Locally in the Workspace

The project exposes build and run as **tasks from the devfile**.

.3. Build the backend using the devfile task
. Open the command palette and run `Tasks: Run Task`.
. Select `devfile: 01-build`.
. Wait for **BUILD SUCCESS**.

.4. Run the backend using the devfile task
. Open the command palette and run `Tasks: Run Task`.
. Select `devfile: 02-run`.
. Keep it running to enable live reload.

.5. Open Quarkus Dev UI and Swagger UI
. When `devfile: 02-run` is running, Dev Spaces should detect that Quarkus is listening on port `8080`.
. Open the endpoint:
* Use the IDE prompt to open port `8080` (recommended), or
* Open the *Ports/Endpoints* view and open/expose port `8080`.
. Open Quarkus Dev UI at `/q/dev-ui/`.
. From Dev UI, open **Swagger UI** (or go directly to `/q/swagger-ui/`).

== Make a Code Change

.6. Modify code and verify live reload + Swagger refresh
. Open `src/main/java/com/neuralbank/api/CreditResource.java`.
. Add a simple new endpoint under `@Path("/api")`:
+
[source,java]
----
@GET
@Path("/hello")
@Produces(MediaType.TEXT_PLAIN)
public String hello() {
    return "hello from workshop";
}
----
+
. Save the file and watch the `02-run` terminal; Quarkus should recompile automatically.
. Go back to Swagger UI and verify the new `GET /api/hello` endpoint appears and works.

== Commit and Push to Gitea

.7. Commit and push from Dev Spaces
. Use the *Source Control* view in the IDE to stage your change, create a commit, and push it.
. Alternatively, use the terminal:

[.console-input]
[source,bash]
----
git status
git add <modified-files>
git commit -m "workshop: demo change from Dev Spaces"
git push origin main
----

== Watch the Tekton Pipeline

. Go to **OpenShift Console -> Pipelines -> PipelineRuns** in project `{user_name}-neuralbank`.
. Identify a new run triggered by the recent push.

The Gitea webhook uses an internal service URL to trigger the EventListener:

----
http://el-neuralbank-backend-listener.{user_name}-neuralbank.svc.cluster.local:8080
----

This avoids TLS certificate issues with self-signed cluster certificates.

== Verify Deployment of the New Version

. Under **Workloads -> Pods**, confirm the Deployment performed a rollout (new pods with a recent timestamp).
. After the PipelineRun finishes, verify the *deployed* Route also has your change.

[.console-input]
[source,bash,subs="attributes+"]
----
export APP_NAME="${APP_NAME:-neuralbank-backend}"
export NS="{user_name}-neuralbank"
export APIKEY_NAME="{user_name}-${APP_NAME}"

SECRET_NAME=$(oc get apikey -n "$NS" "$APIKEY_NAME" -o jsonpath='{.status.secretRef.name}')
API_KEY=$(oc get secret -n "$NS" "$SECRET_NAME" -o jsonpath='{.data.api_key}' | tr -d '\n' | base64 -d)

curl -s -H "X-API-Key: $API_KEY" \
  "https://neuralbank-backend-{user_name}-neuralbank.{cluster_domain}/api/hello"
----

You should see the change reflected in the response.

== Bonus: Edit the MCP Server in Dev Spaces (customer-service-mcp)

The workshop also includes a **Customer Service MCP** component. You can edit and run it in Dev Spaces, and verify the MCP endpoints that expose its tools.

. Open the component in Developer Hub:
* Go to the Catalog and open **customer-service-mcp**
* Click **Open in Dev Spaces**
. Wait for the workspace to be ready (same flow as the backend).
. Run the MCP server in dev mode:
* Use `Tasks: Run Task` → `devfile: 02-run`
. Open Quarkus Dev UI:
* Open port `8080`
* Visit `/q/dev-ui/`
. Validate MCP endpoints (from the Dev Spaces terminal):
+
[.console-input]
[source,bash]
----
curl -s "http://localhost:8080/q/health" | jq .
# SSE endpoint (streams events)
curl -i -N "http://localhost:8080/mcp/sse"
----
+
. Recommended: use Quarkus Dev UI to call tools:
* In Dev UI, open *MCP Server - HTTP/SSE - Tools*
* Select a tool (for example `getCustomer`) and click *Call* to see the response

== Summary

You demonstrated the full cycle **Dev Spaces -> Git -> Tekton -> OpenShift**, aligned with GitOps and the component card in Developer Hub. Developers stay in a consistent environment while the platform applies standards and automation.
