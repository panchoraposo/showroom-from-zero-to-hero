= Update Code with Dev Spaces

This module walks through **edit in web IDE -> commit to Gitea -> Tekton pipeline -> new deployment**, using **Red Hat OpenShift Dev Spaces** and the **neuralbank-backend** component.

== Open the Component in Developer Hub

. Log in to **Developer Hub**.
. Find **neuralbank-backend** in the **Catalog** and open its page.
. Click **Open in Dev Spaces** (or the equivalent plugin action).

If the button is missing, copy the repository URL from Gitea and create a workspace in Dev Spaces manually.

== Wait for the Workspace to Start

. Wait until **DevWorkspace** reaches **Running** state.
. Open the IDE in the browser.

The workspace uses the `devfile.yaml` generated by the template:

[source,yaml]
----
schemaVersion: 2.2.2
metadata:
  name: neuralbank-backend
components:
  - name: tools
    container:
      image: registry.redhat.io/devspaces/udi-rhel8:latest
      memoryLimit: 3Gi
      mountSources: true
commands:
  - id: 01-init-maven
    exec:
      component: tools
      commandLine: <...>
      workingDir: ${PROJECT_SOURCE}
  - id: 02-build
    exec:
      component: tools
      commandLine: <...>
      workingDir: ${PROJECT_SOURCE}
  - id: 03-run
    exec:
      component: tools
      commandLine: <...>
      workingDir: ${PROJECT_SOURCE}
----

== Dependency Analytics (RHDA) in Dev Spaces

This workshop environment recommends and auto-installs the *Red Hat Dependency Analytics* extension (publisher `redhat`, extension `fabric8-analytics`).

Use it to scan your dependencies and open an HTML vulnerability report.

. In the IDE, open `pom.xml`
. Click the *pie chart* icon in the editor title bar, or right click `pom.xml` and choose *Red Hat Dependency Analytics Report...*
. Wait for the *Red Hat Dependency Analytics Report* tab to open and review:
* Vulnerabilities (CVEs) and severities
* Recommended versions / remediation suggestions

NOTE: By default, RHDA writes the report to `/tmp/redhatDependencyAnalyticsReport.html` (while the report tab is open).

== Build Locally in the Workspace

The project defines commands in the `devfile.yaml`, so you can execute them directly from the IDE.

. In Dev Spaces, open the command palette and run `Tasks: Run Task` (or `Devfile: Execute Command`)
. Run `01-init-maven` (one time)
. Run `02-build`
. Run `03-run`

If you want to quickly locate the RHDA report file from a terminal task, run `04-open-rhda-report`.

== Update Quarkus to the Latest Version and Re-run RHDA

For this workshop, start with an older Quarkus (more likely to surface issues in RHDA), then update Quarkus to the latest Red Hat GA build and re-run the RHDA report to compare results.

. In Dev Spaces, run the devfile command `05-update-quarkus-to-3.27.3.redhat-00002`
. Open `pom.xml` again and re-run *Red Hat Dependency Analytics Report...*
. Compare the report before/after the update (vulnerabilities and recommendations may change)

After the update, you can run `06-run-dev-ui-and-swagger` to start dev mode with Dev UI + Swagger UI enabled for Dev Spaces.

== Make a Code Change

In the IDE file explorer, find a REST resource class (e.g., `CreditResource.java`).

Make a small, safe change:

* Add a `GET` endpoint that returns an identifiable message (`/api/hello-workshop`)
* Or change a response body to include a recognizable string

WARNING: Avoid changing artifact names, Dockerfile, or pipeline paths unless the workshop instructs it.

Add the following endpoint inside your resource class:

[source,java]
----
@GET
@Path("/hello-workshop")
@Produces(MediaType.TEXT_PLAIN)
public String helloWorkshop() {
    return "hello-workshop: backend is running";
}
----

If your IDE shows missing imports, add:

[source,java]
----
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;
----

Fix compile errors before continuing; the remote pipeline will fail the same way.

== Commit and Push to Gitea

[.console-input]
[source,bash]
----
git status
git add <modified-files>
git commit -m "workshop: demo change from Dev Spaces"
git push origin main
----

== Watch the Tekton Pipeline

. Go to **OpenShift Console -> Pipelines -> PipelineRuns** in project `{user_name}-neuralbank`.
. Identify a new run triggered by the recent push.

The Gitea webhook uses an internal service URL to trigger the EventListener:

----
http://el-neuralbank-backend-listener.{user_name}-neuralbank.svc.cluster.local:8080
----

This avoids TLS certificate issues with self-signed cluster certificates.

== Verify Deployment of the New Version

. Under **Workloads -> Pods**, confirm the Deployment performed a rollout (new pods with a recent timestamp).
. Try the endpoints again:

[.console-input]
[source,bash,subs="attributes+"]
----
export APP_NAME="${APP_NAME:-neuralbank-backend}"
export NS="{user_name}-neuralbank"
export APIKEY_NAME="{user_name}-${APP_NAME}"

SECRET_NAME=$(oc get apikey -n "$NS" "$APIKEY_NAME" -o jsonpath='{.status.secretRef.name}')
API_KEY=$(oc get secret -n "$NS" "$SECRET_NAME" -o jsonpath='{.data.api_key}' | tr -d '\n' | base64 -d)

curl -s -H "X-API-Key: $API_KEY" \
  "https://neuralbank-backend-{user_name}-neuralbank.{cluster_domain}/api/hello-workshop"
----

You should see the change reflected in the response.

== Summary

You demonstrated the full cycle **Dev Spaces -> Git -> Tekton -> OpenShift**, aligned with GitOps and the component card in Developer Hub. Developers stay in a consistent environment while the platform applies standards and automation.
