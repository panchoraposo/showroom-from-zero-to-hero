= Desplegar el backend con Software Templates

En este módulo desplegarás **Neuralbank Backend** usando un Software Template. Al finalizar tendrás un repositorio en Gitea, una Application en ArgoCD, una ejecución de pipeline en Tekton y la API accesible en OpenShift.

== Prerrequisitos

* Acceso a Developer Hub con tu usuario (`{user_name}`) y password `Welcome123!`.
* Permisos para crear componentes desde templates del catálogo del workshop.

== Paso 1: Abrir “Create” desde un template

. Inicia sesión en Developer Hub en `https://backstage-developer-hub-developer-hub.{cluster_domain}`
. En el menú principal, selecciona **Create**.
. Busca el template **Neuralbank: Backend API**.

== Paso 2: Completar el formulario

Completa los campos:

[cols="1,2"]
|===
| Campo | Valor

| **Name**
| `neuralbank-backend`

| **Owner (usuario de OpenShift)**
| `{user_name}`
|===

Esto crea el namespace `{user_name}-neuralbank` donde se despliegan todos los servicios.

WARNING: No uses espacios en el nombre del repositorio. El owner debe coincidir con tu usuario de OpenShift para que los permisos del namespace queden correctos.

== Paso 3: Crear y esperar el scaffolding

. Haz clic en **Create** (o **Review** y luego **Create** si existe ese paso).
. Quédate en la pantalla de progreso hasta que terminen todos los pasos del scaffolder.

NOTE: Si un paso falla, revisa permisos en Gitea o cuota/recursos del namespace `{user_name}-neuralbank`.

== Paso 4: Verificar el repositorio en Gitea

. Abre Gitea: `https://gitea-gitea.{cluster_domain}`
. Ubica el repositorio `{user_name}/neuralbank-backend`.
. Confirma que existan código fuente, manifiestos, Tekton y `catalog-info.yaml`.

[.console-input]
[source,bash]
----

== Paso 5: Verificar la Application en ArgoCD

. Abre ArgoCD: `https://openshift-gitops-server-openshift-gitops.{cluster_domain}`
. Busca una **Application** llamada `{user_name}-neuralbank-backend`.
. Revisa **Sync Status** y **Health**; si está *OutOfSync*, ejecuta **Sync**.

== Paso 6: Validar el deployment en OpenShift

. Abre la **Consola de OpenShift**.
. Cambia al proyecto **`{user_name}-neuralbank`**.
. En **Workloads -> Pods**, verifica que los pods del backend estén **Running**.

== Entendiendo el modelo de autenticación

El backend generado usa una **AuthPolicy** que soporta **dos métodos de autenticación**:

[source,yaml,subs="attributes+"]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
spec:
  defaults:
    rules:
      authentication:
        api-key-auth:          # Priority 0 — checked first
          apiKey:
            selector:
              matchLabels:
                app: neuralbank-backend
                kuadrant.io/apikey: "true"
          credentials:
            customHeader:
              name: X-API-Key
          priority: 0
        oidc:                  # Priority 1 — fallback
          jwt:
            issuerUrl: https://rhbk.{cluster_domain}/realms/neuralbank
          credentials:
            authorizationHeader:
              prefix: Bearer
          priority: 1
      response:
        unauthenticated:
          code: 401
          body:
            value: '{"error":"Authentication required."}'
----

[cols="1,2"]
|===
| Method | How It Works

| **API Key** (primary)
| Send `X-API-Key` header with a key from a labeled Kubernetes Secret. This is the method used by the scaffolded frontend.

| **OIDC JWT** (secondary)
| Send `Authorization: Bearer <token>` with a valid JWT from Keycloak realm `neuralbank`. Useful for programmatic access if you already have a token.
|===

IMPORTANT: The scaffolded applications use **API Key as the primary authentication method**. The OIDC JWT option is available for Bearer token validation but does not include an interactive login flow. For a full interactive OIDC experience (browser redirect to Keycloak), see the pre-deployed `neuralbank-stack` in xref:09-explore-connectivity-link-oidc.adoc[Module 9].

== Step 7: Try the API Endpoints

The backend exposes REST endpoints through the Kuadrant gateway. Use an API Key to authenticate:

[.console-input]
[source,bash,subs="attributes+"]
----
export APP_NAME="${APP_NAME:-neuralbank-backend}"
export NS="{user_name}-neuralbank"
export APIKEY_NAME="{user_name}-${APP_NAME}"

SECRET_NAME=$(oc get apikey -n "$NS" "$APIKEY_NAME" -o jsonpath='{.status.secretRef.name}')
API_KEY=$(oc get secret -n "$NS" "$SECRET_NAME" -o jsonpath='{.data.api_key}' | tr -d '\n' | base64 -d)

echo "API Key: $API_KEY"

# List customers
curl -s -H "X-API-Key: $API_KEY" \
  "https://${APP_NAME}-{user_name}-neuralbank.{cluster_domain}/api/customers" \
  | jq .

# List credits
curl -s -H "X-API-Key: $API_KEY" \
  "https://${APP_NAME}-{user_name}-neuralbank.{cluster_domain}/api/credits" \
  | jq .
----

== Step 8: Confirm Catalog Registration

. Return to **Developer Hub**.
. Find component **neuralbank-backend** in the **Catalog**.
. Open the entity card and review links to the repository, documentation, and relationships (**API** entity).

== Summary

You deployed the backend through the full path **Hub -> Template -> Gitea -> ArgoCD -> Tekton -> OpenShift**. The API is protected by Kuadrant with **API Key authentication** (primary) and optional OIDC JWT validation. All services are in namespace `{user_name}-neuralbank`.
